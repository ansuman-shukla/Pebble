# Plan: World v1, making the world real

Execution brief for `docs/design/10-world-v1.md` (the bible; read it first). Phase B stays closed until the
**World v1 critic checklist** at the end of this file passes. Decisions D77-D96 are the design; D97 is PR #33; the
fix-now PRs use D100-D104; each stream records its implementation decisions in its own block of 3 from **D105**
(table below).

## How the work runs

- **Before wave 1:** PR #33 (merged), `ansuman/fix/walker-motion` (audit F1/F7/F13) and `ansuman/fix/rest-poses`
  (F5/F6) merge first. X0 branches from `main` only after both fix-now PRs are in. Streams that don't touch their
  files (P1, AS1, G1, U1, R1, L4) may start at once.
- **Waves.** Each later wave branches from `main` after the previous wave is merged. Inside a wave, streams own
  **disjoint files** (the "Owns" lines); anything not listed is read-only for that stream.
- **Seams** (the only files several streams in one wave may touch; append-only rows, the integrator keeps every row):
  - `sim/actions.py` dispatch table rows, `sim/work.py` `WORK_TASKS` rows (each task's handler lives in its owner's
    module), the tick hook list and the system registry in `sim/systems.py`, the line registry
    `observability/lines.py`, role routing rows in `brains/profile.py`, the check registry
    `backend/scripts/checks/__init__.py`.
  - `frontend/src/lib/world/visual-rate.ts`: **owned by B1** (its first PR, day 1); M1, M2, L4 import it read-only.
  - `frontend/src/lib/world/label-store.ts`: **owned by U1**; M1 writes head-bone anchors only through its API.
  - Generated files (`frontend/openapi.json`, `frontend/src/lib/client/*.gen.ts`) are never hand-merged: rerun
    `./scripts/pnpm.sh update-openapi`.
- **Contract.** C1 publishes the **draft** contract v1 models in wave 1 and stays their owner through wave 3: a model
  change is a C1 follow-up PR (plus a decision row if it changes a rule). New actions answer with the existing
  `not_yet` refusal until their stream lands. **Q1 freezes** `contract_v1.json` after the critic checklist passes.
- **Determinism.** X0 gives every system a named RNG stream (`Rng.for_subsystem(seed, "<system>.<purpose>")`);
  new rolls get new stream names and never draw from an existing stream. Each system owns its state dataclass and a
  versioned snapshot block (bible §6.5).
- **Chaotic tests.** `tests/brains/test_living.py` (and run checks that read whole-run statistics) have one owner per
  wave who alone changes their thresholds: **wave 1 X0 for its RNG-stream commit (rebaselined with the 5-seed
  sweep), then S1; wave 2 BR0; wave 3 BR1; wave 4 Q1**. **Probe-first triage:**
  if your change flips such a test, run it on 5 seeds before and after your change (`world_run --seeds 5`, same
  days). If the stat stays in its band on ≥ 4 of 5 seeds after, it is a chaotic flip: hand the sweep to the wave's
  owner, who rebaselines in their PR with the sweep as evidence. Otherwise it is a regression: fix your code. Nobody
  edits a threshold without a sweep.
- **Checks.** X0 creates `backend/scripts/world_run.py` with a check registry; each stream adds its run checks as
  `backend/scripts/checks/<stream>.py` (owned by that stream). Run checks are **aggregates over both seeds**
  (20261028 and 7, 14 days each) unless marked per tick; deed and justice chains are proven by **scenario tests**
  (a scripted set-up, a few game hours), never by hoping a run produces them. A **sale** is one `bought` or `sold`
  event (one buy or sell action, however many lots); bible §2.7's flows give ≈ 13 sales per game day per seed
  (farmers 2, the lord's granary 0.5, rice buyers 3, Tetsu 1.5, Daisuke 1.8, Aiko 1, tools 0.2, the lord's cloth and
  gold 0.75, Goro's dried meat 0.5, band A 1, band B 1).
- Worktrees, ports, verify chain, commit/PR rules: `program.md`/`AGENTS.md`. One branch `ansuman/<type>/<slug>` and
  one PR per stream (stacked PRs if > ~800 changed lines). Snapshot v3 and world generator m4.0 mean fresh runs.
- **Integration per wave:** an integrator merges the wave's PRs in the listed order once approved, reruns the verify
  chain and the wave's checks on `main`, and sends breakage back to the owning stream.

## Wave 1: foundations

### X0 · Seams (S, hours; branches after #33, walker-motion and rest-poses merge)
- **Scope (no behaviour change):**
  1. Split `sim/actions.py` into `actions.py` (dispatch tables start/advance/finish, interrupts, `not_yet`),
     `movement.py` (walk, follow, flee, pace, walk_ahead), `destinations.py` (`_resolve*`, beside), `resting.py`
     (rest, sleep, collapse), `doing.py` (gather, eat, drink), `work.py` (`WORK_TASKS` seam, the work runner, the v0
     task handlers farm/store food/guard/trade/weave/govern) and `exchange.py` (say, pick_up, drop, give,
     store_in_reach). Move tick-summary building out of `sim/simulation.py` into `sim/feed_citizens.py` (moves,
     bodies) and `sim/feed_animals.py` (animal poses).
  2. `sim/systems.py`: the tick hook list (per tick, local dawn, local midnight) and a **system registry**: each
     system registers its name, state dataclass, snapshot (de)serialiser and version; snapshot v3 = v2's core +
     `systems: {name: {version, data}}`. Systems keep per-citizen and per-animal data in their own state keyed by id,
     so later streams never edit `sim/state.py`. No later-wave state is declared here.
  3. Named RNG streams: every existing roll moves to a `<system>.<purpose>` stream; a lint test fails if a module
     draws from another system's stream.
  4. Run harness `scripts/world_run.py` (`--days`, `--seeds`, `--only`) + `scripts/checks/__init__.py` registry.
- **Owns:** `sim/actions.py` + the new modules above, `sim/simulation.py`, `sim/systems.py`, `sim/state.py`,
  `sim/snapshot.py`, `core/rng.py`, `scripts/world_run.py`, `scripts/checks/`, test import updates, and
  `tests/brains/test_living.py` for the RNG-stream commit only (it rebaselines with the 5-seed sweep, then hands the
  file to S1).
- **Acceptance:** verify chain; a 10-day `citizens_run` gives the identical event-type sequence hash before and
  after the split (the RNG stream renames are a separate, last commit with a new baseline); snapshot v3 round-trips
  with an empty and a fake system; v2 snapshots start a new run (D58).
- **Critic:** none visible (refactor).
