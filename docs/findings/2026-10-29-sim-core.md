# Findings: the simulation core (M5, 2026-10-29)

What the engine, the world contract and the event store do, how fast they are, how many events a game day makes, and
what is still rough. The world is the stored planet of the current generator version (seed 20261028) plus the town
spec; citizens come from code, tests or `data/citizens/dev.yaml` (the real 15 arrive with M7).

## Processes

```
            ┌──────────── engine (python -m app.engine) ────────────┐
            │ loads world + town ─▶ resume latest run / new run      │
            │ loop: commands ─▶ brains (M7) ─▶ sim.step() ─▶ store   │
            └─────┬───────────────▲──────────────────────────────────┘
   events, snapshots, runs.tick   │ engine_commands (pause/speed)
   + NOTIFY pebble_events         │ + NOTIFY pebble_commands
            ┌─────▼───────────────┴──────┐
            │          Postgres          │
            └─────▲───────────────┬──────┘
                  │ reads         │ inserts commands
            ┌─────┴───────────────┴──────┐
            │  api (uvicorn app.main)    │  GET /clock /entities[?at] /events, POST /admin/clock
            └────────────────────────────┘
```

- The engine is the only writer of `runs`, `events` and `snapshots`. One transaction per tick: the tick's events, a
  snapshot every game hour, the run's clock/heartbeat, and `NOTIFY pebble_events` with
  `{"run_id", "tick", "first_seq", "last_seq"}` (M8's live feed fetches that range).
- The api writes only `engine_commands` (+ `NOTIFY pebble_commands`); the engine polls them every loop (each tick,
  or every 0.25 s while paused) and stamps `applied_at`.
- `make engine` (Postgres + migrate + `python -m app.engine`); flags: `--new-run`, `--speed 1..60`, `--paused`,
  `--headless --ticks N` (no sleeping), `--citizens PATH`, `--no-citizens`. SIGINT/SIGTERM snapshot and mark the run
  `stopped`; restarting resumes it. After an unclean stop the events past the last snapshot are dropped and simulated
  again (deterministic, so they come out the same).

## The tick

advance durative actions (walkers move along their route, timers complete) → bodies (needs, collapse, death) →
ecology (M6) → perception and interrupts → visits (places within their radius become known) → one `tick_summary`.
Actions from brains arrive between ticks. Interrupts per 03: speech heard since the last tick, worsening need
thresholds, a stranger coming into view, someone known walking up to you (to you or to a spot within 3 m of you,
interrupting once they are within 10 m), night falling, the followed person gone; sleepers wake only on a shout, their name
or getting hurt; collapsed sleepers not before energy 30.

## Events

Every discrete change is exactly one event; continuous per-tick change (walkers' positions, needs drifting) is the
tick's single `tick_summary` (moved citizens + every living citizen's needs). The test replays snapshot + events and
compares with the live state at several checkpoints, and checks that dropping any spawn/item/resource event (or
doubling an item move) breaks the replay. Additions to 06: `citizen_spawned`, `knowledge_changed` (places/people
learned). Events carry a deterministic per-run `seq`; the store gives each a ULID and resolves `cause_seq` to `cause_id`.

## Timings (M-series Mac, `uv run python -m scripts.bench_sim N 24`)

The benchmark keeps every citizen busy (walk between town places, drink when thirsty, greet now and then), far busier
than real citizens; no database. By default everyone knows everyone (a town); `strangers` makes nobody known.

| Citizens | tick mean / p99 / max | actions between ticks (planning) mean / max | events per game day | snapshot |
|---|---|---|---|---|
| 15 | 0.55 / 0.8 / 20 ms | 7 / 48 ms | ~24 400 | 230 kB |
| 100 | 5.9 / 9.8 / 34 ms | 47 / 117 ms | ~177 000 | 850 kB |
| 100 strangers | 3.7 / 5.4 / 27 ms | 49 / 120 ms | ~211 000 | 820 kB |

- Walk planning is the expensive part: town A* with weight 2 takes 1.5 ms on average between town places (max ~60 ms
  around walls); plain A* took 12 ms (max ~190 ms) for routes only ~2 % shorter. Town → forest ~15 ms.
- Persisting: `--headless --ticks 1440` with the 3-person dev cast runs a game day in ~3.5 s including world load
  (~2 ms per tick for the write, ~6 ms on the hourly snapshot tick). An idle day writes ~1 450 events (1.3 MB with
  indexes) and 24 snapshots (~1.1 MB).
- People interrupting (D54). Before, anyone coming into view interrupted: 100 busy citizens had ~47 100 interrupts
  a game day, ~16 400 of them "comes into view". Now only strangers do, and known people walking up to you:

  | 100 busy citizens, per game day | before | after (all known) |
  |---|---|---|
  | comes into view / coming toward you | 16 395 | 0 / 2 240 |
  | speech heard | 30 550 | 25 513 |
  | needs, night, other | 151 | 162 |
  | all interrupts | 47 096 | 27 915 |

  The remaining approaches are mostly housemates walking home to the door their housemate stands at (100 citizens
  share 49 houses). Speech now dominates: the benchmark greets ~4 500 times a day in a crowd, and every greeting
  stops everyone in earshot, as 03 asks. The 15-citizen town drops to ~930 interrupts a day. Knowing everyone costs
  ~2 ms more per tick at 100 (the approach check walks each citizen's known people in view).

## Contract notes

- Durative actions block in game time: `WorldApi.walk_to(...)` returns a handle whose `result` appears when the walk
  ends; `run_until_done(sim, handle, max_ticks)` ticks headless (tests). Starting a new durative action interrupts
  the running one ("You stop walking to do something else.").
- `walk_to` targets: a known place by name (`home` = the citizen's house), a person in view (name if known, else
  appearance), a thing in view (food, water, structures, items on the ground), or a compass direction + rough
  distance (a few steps / a short walk / a long walk / very far). Told-about places are walked to by a fixed rough
  guess (up to 60 m off).
- Reach: 3 m for items and people; drinking needs the well (within 4.5 m of its centre), a river cell, or a cell next
  to a lake; the sea is salty. Gathering takes the citizen's current cell's counter (none inside the town).
- Not yet: `follow`, `fish`, `hunt`, `make_fire`, `feed_fire`, `work`, `attack`, `recall` answer "You can't do that
  yet." (M6/M7, recall in phase B). `flee` is real but there is nothing to flee from until M6's animals.

## Known limits

- No occlusion: walls and hills don't block sight or sound; ranges only.
- Outside the town walkers move between cell centres (~40 m apart) and ignore camp/landmark props; ground height is
  the nearest cell's. Inside the town, routes stay on walkable 0.5 m cells (tested along every leg).
- Town fire baskets/lanterns don't light the night yet (fire arrives with M6).
- Inside the town only the well is drinkable (moat and mill stream aren't).
- Eating or drinking cut short by a new action between ticks changes needs at once; the replay sees it at the next
  `tick_summary`.
- The shared dev database is still at `72d7f061a69c`: the migration was tested (upgrade, downgrade, `alembic check`)
  on a scratch database; `make engine`/`make dev` apply it on first run.
